# 後台三種角色，權限依場地與支聯會切分，用 Email 魔法連結登入

後台分成總管理員、教堂承辦、支聯會承辦。教堂承辦只能看、改自己場地的報名；支聯會承辦只能看自己支聯會的名單與統計，不能修改。權限由資料庫的權限規則（Supabase RLS）強制，不靠前端隱藏。登入用 Supabase 的 Email 魔法連結，不設密碼；帳號只能由總管理員新增，交接時換 Email 即可。

## Consequences

- 報名截止後的修改只有總管理員和該場地的教堂承辦能做。
- 只有總管理員能匯出完整名單；承辦人員只能匯出自己範圍內的資料。大會結束後的年度 Excel 名單也只限總管理員（ADR 0008）。
- 報名中（報名開放到報名截止），教堂承辦可以隨時調整自己場地的課程、午餐、午后動態的名額，或停止、重新開放其報名（2026-10-12 變更；原本只有總管理員能調名額）。總管理員不受這段時間限制。
- 報名中，教堂承辦也可以幫自己場地的課程換教室（2026-10-14 變更：依報名人數換到較大或較小的教室，名額一併調整）。
- 教堂承辦只能改名額、停止狀態與教室這三個欄位，由資料庫限制，不能改課名、說明、排序或所屬場地；直接呼叫 API 也一樣。
- 新增、刪除選項與換時段只有總管理員能做，而且只能在報名開放前；開放後任何角色都不能做。
- 任何人都能直接呼叫 Supabase 的登入 API，從回應看出某個 Email 有沒有後台帳號，也就是她是不是工作人員（2026-10-15 接受）。網站的登入頁不管有沒有帳號，畫面和回應時間都一樣，但擋不住直接呼叫 API。知道了也要能打開她的信箱才登得進去，最壞的情況是被拿來寄詐騙信。要完全遮住，得關掉 Supabase 的 Email 登入，改由網站自己產生連結、用另外的寄信服務寄出；目前不值得多一個要交接的服務。
