# 名額在送出時一次性確認，填表期間不保留

課程、午后動態、午餐的名額在報名送出時由資料庫一次確認並寫入；任何一項額滿，整筆都不寫入，並退回選課步驟、保留其他已填資料、標示「已額滿」。填表期間不先保留名額，因為保留機制複雜，且放棄填寫的人會佔住位子。舊系統的報名與修改是兩個專案、名額鎖不互通而超收，這次報名、修改、取消必須走同一套名額檢查。

## Consequences

- 修改報名時，她原本已佔的名額仍算她的。
- 成對課程的兩堂一起判斷，一堂額滿就兩堂都不能選。
- 總管理員在後台可以超過容量，但必須先確認提示；容量不是資料庫的硬限制，而是報名者送出時的檢查。後台的新增、修改和前台共用同一套寫入與名額檢查的資料庫函式，只是入口不同（#17）。
- **停止報名**的選項在送出時視同額滿，前台也顯示「已額滿」。停止與名額是兩件事：停止時不論名額是否「不限」、有沒有空位都不能新選；重新開放後仍要通過名額檢查。有人取消或名額調高都不會自動重新開放。
- 「她原本已佔的位子」以資料庫裡已儲存的有效報名為準：修改時保留原本的選項不受停止或額滿影響；新加入的選項才檢查。修改中途換走又換回原本的選項，仍算她原本的位子。新選項被拒時整筆修改不寫入，原本的報名完整保留。
- 停止報名和送出報名搶同一把鎖（現有的課程列鎖，午餐、午后動態比照）：停止先完成，之後才拿到鎖的送出被拒；送出先拿到鎖，就照常寫入，停止之後她仍保留位子。調整名額也一樣。
- 成對課程的兩堂在同一個交易裡一起停止、一起重新開放，不會只改到一堂。
- 總管理員在後台可以把人加進已停止的選項，和超收一樣必須先確認提示（例如「這門課已停止報名，確定要加入嗎？」）。確認旗標只是「我知道了」，不是權限：資料庫要先確認呼叫者是總管理員，前台送出的報名不接受這個旗標（ADR 0004 #48 之後課務組、報報組都不能改報名）。
- 名額調低到已報人數以下時，已報的人不受影響，只是之後不能再選，直到有人取消或名額調高。
